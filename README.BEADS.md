# Beads Mode для Spec Kit

Этот документ описывает **Beads‑mode** — альтернативный режим работы Spec Kit, ориентированный на task‑driven development с жёстким контролем контекста, токенов и скорости итераций.

Beads‑mode является **опциональным** и включается явно. Он не заменяет стандартный Spec Kit, а добавляет более строгую и предсказуемую execution‑модель для опытных пользователей.

---

## Что такое Beads‑mode

**Beads‑mode** — это режим инициализации проекта Spec Kit, в котором:

- источником истины для задач является **Beads**
- Spec Kit используется как **структурированный контекст**, а не как драйвер выполнения
- AI‑агент получает только минимально необходимый контекст
- каждая итерация контролируема и воспроизводима

Архитектурно это выглядит так:

- **Spec Kit** — платформа (структура, шаблоны, UX)
- **Beads** — execution engine (задачи, состояние, поток)
- **bd-context.sh** — API для выдачи контекста AI‑агенту

---

## Как включить Beads‑mode

Beads‑mode включается при инициализации проекта:

```bash
specify init my-project --beads
```

Требования:
- установлен Beads CLI (`bd`)
- POSIX shell (bash/zsh)
- на Windows требуется WSL

При включении режима:
- выполняется `bd init`
- проект инициализируется в Beads‑first workflow
- стандартный Spec Kit остаётся нетронутым

---

## Новые команды Beads

В Beads‑mode становятся доступны дополнительные команды (только для `sh`):

| Команда | Назначение |
|------|-----------|
| `beads-implement` | Полный цикл: ready → context → implement → close |
| `beads-sync` | Синхронизация состояния Spec ↔ Beads |
| `taskstobeads` | Импорт задач в Beads |
| `beadstojira` | Экспорт задач Beads в Jira |

### Общие правила

- источник истины — **Beads**
- контекст загружается **только** через `bd-context.sh`
- агенту запрещено напрямую читать `spec.md`, `plan.md`, `research.md`
- уровень контекста контролируется (`brief`, `standard`, `full`)

---

## Сравнение с дефолтным Spec Kit

| Критерий | Default Spec Kit | Spec Kit + Beads |
|--------|------------------|------------------|
| Источник задач | Spec / Plan | Beads |
| Контекст | Файлы читаются агентом | Контекст выдаётся |
| Контроль итераций | Неявный | Явный |
| Повторы контекста | Частые | Минимальные |
| Предсказуемость | Средняя | Высокая |

---

## Экономия токенов (оценочно)

> Значения ниже являются усреднёнными оценками и зависят от проекта и агента.

| Сценарий | Default Spec Kit | Beads‑mode |
|--------|------------------|------------|
| Открытие задачи | 4–6k токенов | 300–800 |
| Одна итерация | 2–3k | 200–400 |
| Крупная фича | 30k+ | 5–8k |

Экономия достигается за счёт:
- отсутствия повторного чтения файлов
- строгого контроля контекста
- отсутствия «контекстного шума»

---

## Скорость разработки

| Workflow | Default | Beads‑mode |
|--------|---------|------------|
| Старт задачи | Медленно | Мгновенно |
| Итерации | Линейные | Быстрые |
| Возврат в контекст | Дорогой | Дешёвый |

Beads‑mode особенно эффективен для:
- длинных задач
- сложных фич
- многоитерационной разработки

---

## Ограничения

- Beads‑mode поддерживает **только POSIX shell (`sh`)**
- PowerShell (`ps`) не поддерживается
- На Windows необходимо использовать **WSL**
- Режим предназначен для опытных пользователей

---

## Кому подходит Beads‑mode

✅ Подходит:
- solo‑разработчикам
- тимлидам и архитекторам
- агент‑driven development
- проектам с длинным жизненным циклом задач

❌ Не подходит:
- для быстрого «hello world»
- для новичков
- если важна максимальная простота

---

## Итог

Beads‑mode превращает Spec Kit из инструмента генерации кода в **управляемую execution‑платформу**.

Он не заменяет стандартный workflow, а предлагает более строгую, быструю и экономичную альтернативу для тех, кто понимает, зачем она нужна.
